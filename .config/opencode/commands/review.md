Review the current changes. Check that the code is correct, concise, readable, and maintainable. Identify obvious security issues, performance problems, and missing tests (or unnececary tests that we can remove again, we dont want useless tests). Avoid suggesting abstractions or small helper functions that are used only once unless they clearly improve the code. Fix simple issues directly in the code, but for larger refactorings, report them by severity. if there's no issues, say so.
